# План: контент и базовое SEO опубликованного сайта

> **Для Гиляны:** выполнение этого плана требует отдельного цикла с использованием `superpowers:executing-plans`.

**Цель:** вычитать все опубликованные маршруты, убрать технические заглушки и неподтверждённые обещания, сделать метаданные и структуру страниц понятными для посетителей и поиска, не добавляя контактов, заявок или интеграций.

**Архитектурный подход:** хранить нейтральные образовательные разделы ипотечных статей в `content/mortgage-programs.ts`, а страничный шаблон выводить именно эти разделы. Убрать все элементы, которые предлагают оставить персональные данные при отсутствии отправки: форму на контактах, на услугах, в каталогах и в калькуляторе. Для контактной страницы оставить только честное статичное сообщение. Проверки дополнятся тестами на SEO, маршруты и отсутствие таких форм; технические проверки дополнят статический аудит собранных HTML-файлов.

**Технологии:** Next.js/Vinext, React, TypeScript, Vitest, ESLint, Vite production build, GitHub Pages.

## Ограничение текущей публикации

Текущий GitHub Pages workflow публикует только `main`, поэтому отдельной опубликованной preview-версии PR сейчас нет. Ручной deploy ветки мог бы заменить публичный сайт и не является безопасной проверкой. Перед созданием PR нужно решение Гиляны: принять локальную production-проверку и review PR до merge с проверкой Pages сразу после merge, либо отдельно разрешить создание независимой preview-инфраструктуры.

## Итоговые границы

- Не публиковать телефон, адрес, почту, Telegram, ссылки, цены, объекты, фотографии, банковские параметры, сроки и обещания результата.
- Не подключать отправку заявок, CRM, БД, API, localStorage или аналитику персональных данных; не оставлять неработающие формы, которые запрашивают имя или телефон.
- Не менять `main` напрямую и не подменять проверку опубликованной версии локальным preview.
