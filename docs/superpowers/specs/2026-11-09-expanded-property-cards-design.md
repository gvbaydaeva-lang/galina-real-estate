# Расширенные карточки ЖК — краткий дизайн

## Задача

Сделать все 18 карточек ЖК в каталогах Москвы, Санкт-Петербурга и Краснодара содержательными для человека, который выбирает квартиру: добавить нейтральное описание каждого проекта на два–три абзаца и отдельный список ключевых особенностей. Убрать из видимой карточки строку с датой проверки сведений.

## Для кого и зачем

Посетителю нужно понять характер проекта, его локацию и заявленную инфраструктуру до личной консультации, а не увидеть только название и район. Карточка остаётся элементом каталога, а не отдельной страницей и не заменяет официальную документацию проекта.

## Границы

- Меняются только данные карточек ЖК, их отображение, стили и тесты.
- Все утверждения пересказывают актуальные официальные страницы конкретных проектов; не добавляются цены, сроки, адреса, условия покупки, обещания доходности, контакты и сведения, которых источник не подтверждает.
- Для каждого ЖК: 2–3 коротких абзаца и от 3 до 5 ключевых тезисов. Тезисы описывают локацию, окружение, инфраструктуру или особенности планирования только когда это прямо заявлено источником.
- Дата проверки остаётся служебным полем для внутренней проверки данных, но не передаётся в видимый текст карточки.
- Официальные URL остаются только в серверном реестре и не показываются посетителю.

## Рассмотренные варианты

1. Короткая подпись под текущей карточкой. Не подходит: не отвечает цели пользователя — информации будет слишком мало.
2. Отдельная страница для каждого ЖК. Позволила бы дать больше деталей, но создаёт 18 маршрутов, навигацию и отдельный SEO-контур, чего задача не требует.
3. Расширить существующую карточку. Выбранный вариант: описание и список особенностей остаются на странице каталога, не меняют маршруты и дают достаточный контекст.

## Решение

В тип `VerifiedProperty` добавляются `description` (массив из двух–трёх абзацев) и `highlights` (массив из трёх–пяти строк). Компонент `PropertyCard` выводит эти блоки после заголовка; строка `Проверено: …` удаляется. Сетка карточек на широком экране становится одноколоночной, чтобы длинный текст оставался читаемым; на телефоне структура сохраняется одной колонкой.

## Проверка

Тесты подтверждают, что у всех 18 карточек есть требуемый объём описания и тезисы, в разметке отображаются описание и тезисы, а дата не попадает в HTML. Затем запускаются полный набор Vitest, линтер, статическая сборка с базовым путём GitHub Pages и проверка пробелов в diff.
