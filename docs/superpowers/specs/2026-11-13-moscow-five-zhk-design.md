# Этап 3: пять ЖК Москвы — дизайн решения

## Цель

Доработать карточки и сохранённые URL пяти московских ЖК — «Символ», «Событие», Shagal, «ЗИЛАРТ» и «Левел Мичуринский» — до уровня утверждённой страницы «Острова», не меняя сам «Остров», другие города, меню, футер и существующие фотографии.

## Пользовательский результат

Покупатель видит в каталоге название, фото, застройщика, район, подтверждённую стартовую цену и характеристики, а на странице ЖК — единые блоки о проекте, локации, подтверждённых квартирах, планировках, корпусах/сроках, ипотечном калькуляторе и заявке. Если показатель не подтверждён, он не отображается как факт: вместо него используется официальная ссылка на выбор квартиры.

## Цели

- Обновить только пять указанных московских записей в `catalog-cities.ts`.
- Ввести данные квартир как типизированные строки с комнатностью, площадью, ценой и, где нужно, этапом/источником.
- Сделать общий переиспользуемый компонент детальных секций для пяти новых страниц; существующий Ostrov-only блок не переписывать.
- Передавать в калькулятор только подтверждённую цену выбранной секции/этапа.
- Передавать в `InquiryForm` название ЖК и выбранный тип квартиры; не имитировать отправку.
- Сохранить существующие URL и изображения карточек.

## Не входит в работу

- Изменение данных или разметки «Острова».
- Изменение шести ЖК Санкт‑Петербурга, шести ЖК Краснодара, меню, футера и других разделов.
- Добавление непроверенных цен, планировок, ставок, фотографий или прав на материалы.
- Подключение серверной доставки заявок.
- Публикация в GitHub Pages или на действующий сайт.

## Подходы

1. **Общий data-driven шаблон (выбран).** Расширить тип данных, создать один компонент `MoscowPropertySections` и описывать пять ЖК данными. Это минимизирует дублирование и делает раздельные этапы/цены явными.
2. **Пять условных блоков в route-файле.** Быстрее на старте, но создаёт повторяющуюся разметку и риск смешать данные этапов; отклонён.

## Архитектура

`VerifiedProperty` получает необязательные поля для коммерческих данных: таблицу типов квартир, секции этапов/корпусов, ссылку на официальный подбор и значение стартовой цены для калькулятора. Компонент карточки универсально выводит кнопки только для новых пяти страниц и сохраняет отдельное поведение «Острова». Страница маршрута подключает новый компонент только если у объекта есть новые секции; старый Ostrov-only JSX остаётся нетронутым.

Планировки не скачиваются и не копируются: для пяти ЖК выводится ссылка на официальный подбор квартир, поскольку право на использование изображений не подтверждено. В таблице подтверждённых типов будет выбор строки; выбранная строка синхронно передаётся в заявку и, если у неё есть числовая цена, в калькулятор. Для «ЗИЛАРТа» выбор цены отсутствует, поэтому калькулятор остаётся без автоподстановки.

## Решения по проверке дизайна

- Для официального подбора используются прямые страницы проектов/квартир, а не новостные страницы. Для Shagal — `https://etalongroup.ru/msk/object/shagal/flat/`; для «Символа» и «События» — официальные страницы проектов с CTA застройщика; для «ЗИЛАРТа» — текущая официальная страница ЛСР; для «Левел Мичуринского» — страницы этапов 1–2 и 3–4.
- Shagal публикуется с общим подтверждённым стартом и отдельными подтверждёнными строками студий/1-комн. без вывода предполагаемых цен по всем комнатностям.
- «ЗИЛАРТ» публикуется без цены «от» и без автоподстановки цены, с честной ссылкой на официальный подбор.
- Источники и дата проверки фиксируются в данных объекта; новые фотографии и планировки в репозиторий не добавляются.
- Тесты отдельно проверяют сохранение изображений, раздельность этапов, отсутствие выдуманной цены «ЗИЛАРТа», передачу выбранного типа и отсутствие ложной отправки формы.

## Проверка

- Тесты на пять карточек, наличие кнопок, разделы страниц, раздельные этапы, отсутствующую цену «ЗИЛАРТа», контекст формы и корректную цену калькулятора.
- `npx vitest run`, `npm run lint`, `npx tsc --noEmit` и `npm run build` в worktree.
- Локальная проверка пяти URL на desktop и mobile viewport: карточки, переходы, кнопки, таблицы, калькулятор, форма, отсутствие горизонтального overflow.
